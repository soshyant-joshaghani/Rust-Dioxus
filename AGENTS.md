# AGENTS.md — AI development contract

Read this file before architectural changes in Rust-Dioxus.

Rust-Dioxus is a product-agnostic foundation in Rust end to end: Dioxus 0.7 client (web, desktop, mobile) + Rust API (Axum + SQLx + Tokio) + PostgreSQL + Redis. Implement features inside this architecture. Do not reshape it as FastAPI, Hono, Elysia, Go, or a Dioxus fullstack app.

## Start here

| Question | Answer |
|----------|--------|
| What to read first? | This file → [`__plans__/PROGRESS.md`](__plans__/PROGRESS.md) → [docs/architecture.md](docs/architecture.md) → [CONTRACT.md](../../../CONTRACT.md) |
| Where does a feature go? | `backend/src/modules/apps/<name>/` and `frontend/src/modules/apps/<name>/` + `frontend/src/routes/dashboard/<name>.rs` |
| What is the reference? | `backend/src/modules/apps/sample/` (notes) and `frontend/src/routes/dashboard/sample/notes.rs` |
| Where is business logic? | Service |
| Where is database access? | Repository |
| How does the UI call the API? | The feature's `api.rs`, through `modules/base/utils/http.rs` (reqwest). Base URL from `config::api_base_url()` |
| How do migrations work? | SQL files in `backend/migrations`, applied when the API starts |
| How are jobs added? | Enqueue from a service after the write succeeds; handle in the worker |
| How to run it? | `__ctrl__\rust-dioxus-ctrl.bat dev run all`, then `native run desktop` for a native window |

## Plan loop

1. Take the first eligible `pending` stage in `__plans__/PROGRESS.md`, or the stage the user named.
2. Mark it `in_progress`.
3. Implement it.
4. Run `__ctrl__\rust-dioxus-ctrl.bat test all` for the touched surface.
5. Mark `done` only when tests pass.

Do not gitignore `__plans__/`.

## Backend layers

Route (Axum handler) → Service → Repository (trait, SQLx) → PostgreSQL

| Layer | Responsibility |
|-------|----------------|
| Route | HTTP only: parse, call a service, shape the response |
| Service | Rules, authorization, cache, enqueue |
| Repository | Queries and writes only |
| Core | Config, database, cache, jobs, security, errors, docs pages |

Errors are `AppError` in `backend/src/core/error.rs`. The response is always `{"detail": "..."}` with the status from [CONTRACT.md](../../../CONTRACT.md). Do not invent a second error envelope.

## Frontend (Dioxus)

- One crate for every platform. Features `web`, `desktop`, `mobile`; `dx` selects one from `--platform`. Do not fork per-platform UI. Gate platform code with `cfg(target_arch = "wasm32")` or `cfg(target_os = ...)`, not with new crates.
- The client is HTTP-only. Do not add Dioxus server functions or import backend crates: `frontend/` must keep running against every FoxG backend (Fast-Dioxus, Elysia-Dioxus, Hono-Dioxus).
- Modules only under `modules/base/` and `modules/apps/<name>/`. There is no `components/` folder. UI primitives live in `modules/base/ui`.
- Pages live in `routes/` and are listed in the `Route` enum in `routes/mod.rs`. The authenticated pages sit inside `#[layout(DashboardLayout)]`.
- State: signals; shared state through context (`use_auth`, `use_theme`). Persist with `modules/base/stores/storage.rs`, never `web_sys` directly.
- Tailwind classes on elements, written out in full (Tailwind scans `src/**/*.rs`; do not build class names with `format!` fragments). Tokens only in `frontend/tailwind.css`. `assets/tailwind.css` is generated by `dx`.
- Do not hard-code the API origin. Use `config::api_url(path)` through `http.rs`.
- Keep `dioxus` in `frontend/Cargo.toml` and `DX_VERSION` in `__ctrl__/lib/runtimes.py` on the same version.

## Data

- PostgreSQL is the system of record. The schema is Fast's; new tables go in `backend/migrations/NNNN_name.sql` with `IF NOT EXISTS`.
- Redis cache helpers no-op when Redis is down. Do not cache auth.
- Sample notes is the cache example: list and get write the cache, writes invalidate the owner prefix.
- Jobs use the Redis list protocol in the contract. Do not add a second queue library.

## What not to do

- Do not port Python, Hono, or Go shapes into this kit. Follow the contract.
- Do not turn the kit into a product (CMS, shop, AI app).
- Do not put business rules in routes (backend) or in pages beyond calling `api.rs` (client).
- Do not add a dependency without a reason. Every client dependency must build for wasm32, desktop, Android, and iOS.

## Definition of done

- Module files in the right places, on both sides
- Migration if tables changed
- Auth on anything that is not public
- Tests for behavior that can fail
- `test all` green (backend tests, client tests, wasm32 check)
- `__plans__/PROGRESS.md` updated when a stage was in progress
